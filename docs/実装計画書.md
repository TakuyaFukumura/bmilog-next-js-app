## 1. 目的と進捗管理方法

要件定義書と設計書に記載された決定事項を、依存関係に沿って実装するための作業計画である。仕様の詳細や確定済みの設計判断は関連文書を正とし、本書では実装順序・完了条件・進捗を管理する。

- 各ステップの状態を「未着手」「進行中」「完了」「保留」で管理し、作業開始時・完了時に更新する。
- 作業項目のチェックは、変更と必要な確認が済んでから付ける。未完了の項目はチェックしない。
- 保留が発生した場合は、理由と解消に必要な作業を当該ステップに記録する。
- 仕様の変更や新たな決定は、先に要件定義書・設計書へ反映し、その内容に合わせて本書を更新する。
- 各ステップの完了条件を満たした後に、ステップ状態を「完了」にする。

## 3. 実装ステップ

### ステップ0：実装準備・データ配置

**目的:** 既決事項とリポジトリの現状を確認し、安全に実装を始められる状態にする。

**作業項目**

- [ ] 要件定義書・設計書の決定事項と受け入れ条件を確認する。
- [ ] `data/` の除外設定を確認し、匿名サンプルCSVのみGit管理できるようにする。実データ用ファイルは引き続きGit管理対象外とする。
- [ ] `data/weight-sample.csv` と `data/profile-sample.csv` を、決定済みのヘッダー・値の形式に合わせて用意する。
- [ ] サンプルデータに個人を特定できる情報や実測値が含まれていないことを確認する。
- [ ] CSV読込・検証の配置と、サーバー側でページごとに最新内容を読む方法をNext.jsの現行構成に合わせて確定する。

**完了条件**

- サンプルデータの形式が要件定義書と一致し、匿名である。
- サンプルCSVはGit管理可能で、実データ用CSVはGit管理されない設定になっている。
- 以降の実装で未決の高優先事項が残っていない。

### ステップ1：CSV読込・解析・検証

**目的:** 2つのCSVをサーバー側で読み込み、全データを検証してから後続処理へ渡す。

**作業項目**

- [ ] `csv-parse` を追加し、UTF-8 BOM、LF／CRLF、完全な空行、値の前後空白について決定済みのルールを実装する。
- [ ] 測定CSVとプロフィールCSVのヘッダー名・列順・列数を検証する。
- [ ] 必須値、日付形式・実在日付、数値形式・許容範囲・精度を検証する。
- [ ] 同日重複とJST基準の未来日付を検出する。
- [ ] 検出可能な複数の不正を収集し、ヘッダーを含むファイル上の行番号と理由を関連付ける。
- [ ] 不正がある場合は部分データを返さず、読み込み失敗と有効な空データを区別する。
- [ ] 体重を読み込み時に小数第1位へ四捨五入し、日付順に並べる。
- [ ] ページ表示ごとにファイル内容が反映されるよう、サーバー側のキャッシュを抑止する。
- [ ] 正常系、空データ、BOM・改行、各種不正、複数エラー、行番号、部分表示しないことをテストする。

**完了条件**

- 有効な2つのCSVから型付けされたデータを取得できる。
- 不正なCSVを全体エラーとして扱い、問題の行番号と理由を確認できる。
- ヘッダーのみの測定CSVはエラーではなく空データとして扱える。
- CSV検証の単体テストが通る。

### ステップ2：BMI計算・期間データ生成

**目的:** UIに依存しない計算処理と期間抽出を実装し、境界条件をテストする。

**作業項目**

- [ ] 身長と体重からBMIを計算し、小数第1位表示用の値と成人向け区分を生成する。
- [ ] 目標との差分を「実測 − 目標」で計算し、小数第1位で表示できるようにする。
- [ ] BMI 18.5以上25未満に対応する体重範囲を身長から算出する。
- [ ] JSTの今日を基準に、全期間・1か月・3か月・6か月の表示データを抽出する。
- [ ] 暦月の開始日計算、月末補正、期間の両端を含むことを実装する。
- [ ] 初期表示・期間変更時に、表示範囲内の最新記録を選択対象にできるデータを返す。
- [ ] BMI区分境界、丸め、差分の符号、標準体重範囲、JST日付、月末、期間境界、空期間をテストする。

**完了条件**

- 計算結果と期間抽出が決定済みルールに一致する。
- JST・暦月・境界日のテストを含む単体テストが通る。

### ステップ3：サマリー・グラフ・記録表示

**目的:** 決定済みの情報配置と操作性を備えたBMI画面を実装する。

**作業項目**

- [ ] 最新記録、BMI・BMI区分、現在の目標体重との差分を画面上部に表示する。
- [ ] 全期間・1か月・3か月・6か月の期間切替を実装する。
- [ ] Rechartsで体重推移、目標体重の基準線、BMI標準範囲の帯を表示する。
- [ ] 縦軸を記録値・目標線・BMI標準帯を含むよう調整し、最大1,000件の記録を表示・選択できるようにする。
- [ ] 記録点を選択すると、グラフ下の詳細欄に日付・体重・BMIを表示する。初期選択と期間変更時の選択は表示範囲内の最新記録とする。
- [ ] グラフ情報のテキスト代替として、表示中の全記録を折りたたみ可能な表に表示し、100件ずつページ分割する。
- [ ] 空データ、CSVエラー、読み込み失敗を、それぞれ異なる状態として表示する。
- [ ] キーボード操作、視認可能なフォーカス、色以外の識別、ライト／ダーク両テーマのコントラスト、スマートフォン表示を整える。
- [ ] BMI表示が診断ではない旨を画面に明記する。
- [ ] 期間切替、点選択、表のページ切替、空状態・エラー状態、テーマ表示をコンポーネントテストで確認する。

**完了条件**

- サマリー・グラフ・期間切替・記録詳細・テキスト代替が一連の画面で利用できる。
- マウスだけでなくキーボードでも主要な操作ができ、モバイル幅でも主要情報を確認できる。
- 関連するコンポーネントテストが通る。

### ステップ4：アプリ統合・既存機能整理

**目的:** BMI画面をトップページとして統合し、今回の設計で不要となるサンプル機能を整理する。

**作業項目**

- [ ] トップページをサーバー側でCSVを読み込むBMI画面に置き換え、グラフ等のクライアント処理と責務を分ける。
- [ ] 既存ヘッダーとダークモードを維持し、ページタイトル・説明などのメタデータをBMIアプリに合わせる。
- [ ] SQLiteメッセージ機能を削除する。対象には `/api/message`、DB処理、関連型・テスト、メッセージ固有の表示・説明を含める。
- [ ] 不要になった依存関係や設定がないか確認し、削除はBMI画面に不要なものに限る。
- [ ] READMEの機能説明・構成・データ配置・実行方法・テスト説明を新しい実装に合わせて更新する。
- [ ] トップページ統合後の画面と既存の共通コンポーネントのテストを確認する。

**完了条件**

- `/` がBMI・体重可視化画面を表示し、サンプルメッセージを参照しない。
- SQLiteメッセージ機能が画面・API・テスト・説明に残っていない。
- READMEとメタデータが実際の機能に一致する。

### ステップ5：受け入れ確認・リリース準備

**目的:** 要件定義書の受け入れ条件を実装と照合し、完了を記録する。

**作業項目**

- [ ] 要件定義書の受け入れ条件1〜9を実装・テスト結果に照らして確認する。
- [ ] `npm test` を実行し、全テストが通ることを確認する。
- [ ] `npm run lint` を実行し、エラーがないことを確認する。
- [ ] `npm run build` を実行し、本番ビルドが成功することを確認する。
- [ ] 主要ブラウザーとPC／スマートフォン幅で、期間切替、グラフ選択、空状態、エラー状態を確認する。
- [ ] キーボード操作、色コントラスト、グラフのテキスト代替を受け入れ条件に照らして確認する。
- [ ] 変更差分に個人データ、不要ファイル、デバッグコードが含まれていないことを確認する。
- [ ] 本書の全ステップ状態・完了日と文書ステータスを更新する。

**完了条件**

- 受け入れ条件が確認済みで、テスト・lint・buildが成功している。
- 未解決事項がある場合、その内容と対応方針が関連文書に記録されている。
- 実装計画書の全ステップが完了になっている。
