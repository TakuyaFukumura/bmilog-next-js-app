## 1. 目的と進め方

本書は、要件定義書に記載されたBMI・体重変化可視化アプリを、実装可能な構成・処理・テストへ具体化するための設計メモである。

未決事項は「4. 設計上の確認事項」に質問単位で記録する。決定は一度に一問ずつ行い、回答後に決定内容と日付を記録して本書へ反映する。決定前の案は確定仕様として扱わない。

## 2. 前提と現状

### 2.1 要件定義書で決定済みの前提

- 利用者は本人一人で、初期版は匿名サンプルCSVのみを利用する。
- 体重記録は `data/weight-sample.csv`、プロフィールは `data/profile-sample.csv` から読み込む。実データ用ファイルはGit管理しない。
- 体重記録には日付と体重、プロフィールには身長と現在の目標体重を保持する。
- CSVはページ表示ごとに読み直し、全体を検証してから表示する。不正行があれば部分表示せず、ファイル上の行番号と理由を案内する。
- BMI、期間切替、目標との差分、グラフ、空状態、JST基準、アクセシビリティ、対応ブラウザー、記録件数などの詳細は要件定義書を正とする。

個々のCSV列、値の範囲、BMI区分、表示ルールおよび受け入れ条件は本書に重複して定義せず、要件定義書を参照する。

### 2.2 リポジトリの現状

- Next.js App Router、React、TypeScript、Tailwind CSSを利用している。
- 現在のメイン画面と `/api/message` は、SQLiteからサンプルメッセージを取得して表示する構成であり、BMI・体重記録の実装はまだない。
- ダークモード切替、共通ヘッダー、Jestテストが存在する。
- BMI機能を追加する際に、既存のメッセージ表示・SQLiteを残すか、置き換えるかは決定していない。

## 3. 設計案

以下は検討を進めるための仮案であり、確認事項の回答によって変更する。

### 3.1 処理の流れ

1. サーバー側で測定CSVとプロフィールCSVを読み込む。
2. CSVを解析し、形式・必須項目・値・日付・重複などを検証する。
3. すべて有効な場合に限り、体重を要件定義書の精度に正規化し、日付順に並べる。
4. プロフィールの身長を使って各記録のBMIとBMI区分を計算する。
5. 最新記録・目標体重との差分・BMI標準範囲を含む表示用データを作る。
6. サマリー、期間切替可能なグラフ、記録がない場合の空状態を表示する。

CSV読み込み・解析・検証・計算と画面表示を分離し、画面コンポーネントにCSV解析やBMI計算の詳細を持たせない構成を想定する。

### 3.2 仮のモジュール責務

| 責務 | 想定する内容 | 設計上の注意 |
| --- | --- | --- |
| データ取得 | CSVファイルをサーバー側で読み込む | ファイルパスと実行環境での配置を決定する |
| CSV解析・検証 | ヘッダー、列、値、行番号を検査する | 測定CSVとプロフィールCSVのエラーを一貫して扱う |
| ドメイン計算 | BMI、BMI区分、目標との差分、標準範囲を計算する | 入力・出力を明示し、画面に依存しない関数にする |
| 表示用データ生成 | 期間に応じた記録、最新値、グラフ用系列を作る | 全期間と移動期間の境界をJST基準で扱う |
| UI | サマリー、グラフ、期間切替、空状態、エラーを表示する | キーボード操作とテキストによる代替を含める |

実際のファイル名・配置とサーバー／クライアントの境界は、確認事項への回答後に確定する。

### 3.3 エラーと空状態

- 不正なCSVは全体を表示せず、対象ファイル、行番号、理由が利用者に分かる状態にする。
- CSV読み込み失敗は「記録がありません」と区別し、成功した空データとして扱わない。
- ヘッダーだけのCSVは要件どおりエラーにせず、空グラフと「記録がありません」を表示する。
- 画面に内部例外やファイルシステムの詳細をそのまま表示しない。利用者向けメッセージと開発者向け診断情報の扱いは別途決定する。

### 3.4 テスト方針案

- BMI・目標との差分・BMI標準範囲などの計算は、境界値を含む単体テストで検証する。
- CSV解析と検証は、正常系・空データ・各不正ケース・複数エラー・行番号を含むテストで検証する。
- 期間切替はJSTの日付境界、記録が期間端にあるケース、記録がない期間を検証する。
- 画面テストでは期間切替、記録点の情報表示、エラー、空状態、キーボード操作を確認する。
- 受け入れ条件との対応を保ち、未決事項が確定した時点で具体的なテストケースへ落とし込む。
